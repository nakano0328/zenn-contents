## はじめに

VLM（Vision Language Model）を実際に触ってみたくて、「ポーズで将棋の駒を操作する将棋」＝VLM将棋を作りました。

やっていることは単純で、

- カメラで人物を撮影する
- 画像をVLM（Gemini）に送る
- ポーズから駒（歩/金/銀/角/飛）を1つ判定する
- 判定された駒だけ動かせるようにする

という流れです。

VLMは「画像から意味を取り出す」ところまでまとめて面倒を見てくれるので体験としてはかなり楽しい一方、作ってみると調整の難しさもはっきり出ました。この記事では、失敗から直していった流れをそのまま書きます。

## 作ったもの（構成）

全体のデータの流れはこうです。

```text
カメラ → 画像取得 → VLM → 駒判定 → ゲーム制御
```

ファイル構成は次の通りです。

- `camera.js`：撮影して画像をbase64で取得
- `ai.js`：VLMに投げて判定
- `npcLogic.js` / `pvpLogic.js`：ターン制御などゲーム側
- `shared.js`：盤面・合法手・描画
- `index.html`：UI

## 最初の実装：とにかく1文字だけ返させる

最初は「とりあえず動くものを作る」を優先して、VLMの返答は1文字に縛りました。
駒の候補は「歩/金/銀/角/飛」の5つです。

```js
const response = await fetch(
  `https://generativelanguage.googleapis.com/v1/models/${MODEL}:generateContent?key=${API_KEY}`,
  {
    method: "POST",
    body: JSON.stringify({
      contents: [
        {
          parts: [
            {
              text: `
歩 / 金 / 銀 / 角 / 飛 のどれかを1文字で答えてください
`
            },
            {
              inlineData: {
                mimeType: "image/png",
                data: base64Image
              }
            }
          ]
        }
      ]
    })
  }
);
```

この段階でもゲームとしては一応成立します。判定結果を受け取って、その駒だけ動かせばいいからです。

## 問題：外したときに「何が悪いのか」分からない

ただ、少し遊ぶとすぐに詰まります。

- なぜ外したのか分からない
- ポーズが悪いのか、画像の切り出しが悪いのか判断できない
- プロンプトを変えても良くなったのか悪くなったのかが分からない

結果として、当たった・外れたの理由が分からず、改善の打ち手を決められない状態になっていました。

当たっているときは問題ないのですが、外れた瞬間に原因を追えないため、調整が進みませんでした。

---

## 修正：判断基準を足す（スコアを返させる）

そこで方針を変更しました。

判定（piece）はこれまで通り1つ返してもらいつつ、同時に「各候補のスコア」を返させて、こちらで観測できるようにします。

### 変更後の出力仕様（プロンプトの狙い）

- 候補（歩/金/銀/角/飛）それぞれに 0〜100 のスコアを付ける
- 最も高いものを `piece` として返す
- 返答はJSONのみ

```text
以下の候補それぞれについて0〜100でスコアを出してください：

歩 / 金 / 銀 / 角 / 飛

その上で最も高いものを piece として選んでください。

JSON形式で返してください：
{
  "piece": "...",
  "scores": {
    "歩": 0-100,
    "金": 0-100,
    "銀": 0-100,
    "角": 0-100,
    "飛": 0-100
  }
}
```

### ai.js（要点）

```js
const data = await response.json();

const text = data.candidates?.[0]?.content?.parts?.[0]?.text;
const parsed = JSON.parse(text);

const piece = parsed.piece;
const scores = parsed.scores;

console.log("AIスコア:", scores);
```

「当たり外れ」だけでなく「迷い具合」まで見えるようにするのが狙いです。

## UIにもスコアを出す

consoleだけだと、実機確認や画面共有のときに見落としやすいので、画面にも出すようにしました。

表示は1行のカンマ区切りにしています。

```text
AIスコア: 歩: 10, 金: 30, 銀: 20, 角: 60, 飛: 90
```

カメラの近くに出しておくと、「今の入力が何に寄っているか」がすぐ分かります。

---

## 効果：調整の方向性が決められる

スコアが見えると、外れた時に原因の切り分けができます。

例えばこういう時：

```text
歩: 45, 金: 47, 銀: 46
```

この場合、そもそも入力が曖昧で、モデルが迷っています。ポーズ側（動き）や画像側（切り出し）を見直すべきだと判断できます。

逆にこういう時：

```text
飛: 90
```

強い確信で誤認識しています。ポーズが紛らわしいか、切り出し領域が意図とズレている可能性が高い、という読みになります。

「どこをいじると改善しそうか」を決められるようになったのが大きいです。

---

## さらに問題：盤面に存在しない駒が返ってきてゲームが止まる

もう1つハマったのがこれです。

- AIが「飛」と判定する
- でも盤面には飛がもう存在しない（取られている）

プロンプトで「盤面に無い駒は出すな」と言っても、完全には防げませんでした。
このままだとゲームが詰むので、仕様として「不正な入力はパス扱い」にして進行を止めないことにしました。

```js
if (!game.hasPiece(piece)) {
  game.passTurn();
  return;
}
```

VLMの出力を正しいと信じ切るより、ゲーム側で吸収する方が結果的に安定します。

---

## ついでに：成りを入れて将棋っぽさを足す（最小構成）

5×5でも、それっぽさを出すなら成りが欲しくなります。
ここは最小構成で、歩と銀だけ成れるようにしました。

```js
if (!piece.promoted && y === 0) {
  piece.promoted = true;
}
```

```js
if (piece.promoted) {
  return getGoldMoves(...);
}
```

成り駒は金として扱います。

## 結論：VLMは強力だが、チューニング前提

今回VLMを触って一番感じたのは次の点です。

```text
VLMはセンサを増やさなくても情報量を稼げる。
ただし情報量が多いぶん、チューニングが必須になる。
```

良いところは次の通りです。

- カメラ1つで多くの情報を扱える
- センサを何種類も用意しなくていい
- UIとして直感的で、遊びに落とし込みやすい

一方で難しい点は次の通りです。

- 判断基準が見えないと調整できない
- 出力は揺れる前提で設計が必要
- 観測と吸収を入れないと運用が辛い

---

## おわりに

今回のVLM将棋では、

- スコアを可視化して「何が起きているか」を観測できるようにする
- 変な出力が来てもゲーム側で吸収して進行を止めない

この2つを入れたことで、VLMを“当てるだけ”から“調整して使う”に変えられました。

VLMはカメラ1つで多くの情報を扱える反面、入力も出力も揺れやすいので、チューニング前提で設計しておくのが大事だと感じました。
